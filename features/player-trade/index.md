# 玩家面对面交易

## 能力

玩家可在同一地图点击另一名角色，从角色菜单发起双人交易。受邀方可接受或拒绝；接受后双方进入独立交易室，同时打开物品栏。

## 交易内容

- 每一方最多放入 9 格物品；堆叠物品先输入数量，再由服务端确认是否加入。
- 可追加不超过当前持有量和客户端整数范围的金币。
- 交易室显示双方形象、物品、金币、最近 6 条聊天消息和确认状态。
- 窗口按 `UIWindow2.img/CashTradingRoom` 的 654x566 画布定位：双方铭牌位于顶部两个人物预览下方，物品图标落入左右各 5 行的格栅，金币行、右侧聊天记录与输入框分别对齐 NX 白色区域。
- 任一方确认后都不能继续追加物品或金币；只有双方都确认且服务端返回成功，交易才算完成。

## 状态与错误

- 对方忙碌、死亡、离开地图或房间关闭时，不进入交易或立即结束并显示原因。
- 背包空间、金币上限、唯一物品或客户端物品数据不一致会显示服务端失败结果。
- 任一方取消或按 Escape 会退出交易；窗口关闭后恢复普通 UI 输入。

## 约束

客户端只发送交易意图并展示服务端回包，不预先移动物品或扣除金币。linked server 在同一交易会话锁内重新核对交易状态、来源背包物品、数量、目标槽位、现金/宠物和不可交易标志，再原子移出来源物品并公开报价。

## 验收

- `tools/verify/trade-ui-nx.cpp`、`tools/verify/trade-layout.cpp` 与 `tools/verify/player-context-menu.cpp` 分别校验交易室底图与 origin、五行物品格栅/金币/聊天几何和右键菜单交易行命中。
- 真实浏览器验收已通过右键菜单「交易」行进入交易室并留存截图；该轮只覆盖入口与房间呈现，未完成物品/金币的完整交易事务，提交语义不在该轮范围内；客户端状态与封包解析由 `trade-state.cpp`、`trade-item-parser.cpp` 覆盖，最终以 linked server 校验为准。
