# 宠物拾取后的掉落移除收敛

## Context

linked server 已在宠物拾取成功后发放物品或金币，并用 mode 5 广播掉落移除。客户端旧实现只处理 mode 0、1、2；mode 5 到达 `Drop::expire` 后没有状态转换，导致奖励已经到账但地图物品永久保留，宠物还会继续追踪同一 oid。mode 1 的失活对象也没有从容器擦除。

## Change Summary

- 新增独立掉落移除协议解析，明确 mode 0/1/2/4/5 的字段宽度和表现策略；mode 5 完整消费 cid 与宠物槽位。
- 宠物拾取使用宠物固定位置播放淡出，角色或宠物不可见时仍原地淡出；动画开始即把掉落置为不可再次拾取，结束后从对象表擦除。
- mode 1/4 直接擦除对象；未知模式记录警告并按服务端权威移除结论安全删除，避免未知表现阻断地图处理。
- 宠物目标在掉落进入不可拾取状态时立即结束，不等待淡出动画结束；玩家手动拾取搜索也跳过动画中的掉落。
- WebUI 验收新增当前宠物目标 oid 和精确掉落存在性探针，要求服务端确认计数增长后同一 oid 在限定时间内消失且不再是当前目标。

## Impact Surface

掉落移除封包解析、地图掉落生命周期、宠物拾取目标状态和真实浏览器宠物验收。服务端代码、数据库 schema、环境变量和宠物奖励规则不变。

## Notes / Compatibility

继续使用 v83 既有 opcode 与 linked server 现有 mode 5 负载；玩家拾取动画保持原行为。未知模式只改变客户端表现对象的收敛方式，不修改服务端背包或金币结论。
